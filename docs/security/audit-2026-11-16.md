## Détail

### S1 — Évasion vers l'hôte par un compose client (Critique, 9.9)

`CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H`

Un client qui déploie son propre `docker-compose.yml` est contrôlé par
`lib/compose-safety.ts` à chaque déploiement. Le correctif refuse notamment :

- **Montages hôte** : sources absolues, `~`, remontées `..`, `docker.sock`,
  `type: bind` vers l'hôte, et montages `npipe` / `cluster` ;
- **Volumes par pilote** : `driver` / `driver_opts` (dont bind de la racine),
  volumes externes ou avec `name` forcé ;
- **Isolement relâché** : `privileged`, `network_mode: host` ou rattachement à
  un autre conteneur/service, `pid`/`ipc`/`uts`/`userns_mode`/`cgroup` partagés,
  `cap_add`, `devices`, `device_cgroup_rules`, `security_opt`, `volumes_from`,
  `cgroup_parent`, `runtime`, `isolation` ;
- **Contenu non vérifié** : `include` et `extends.file` ;
- **Réseaux** : réseaux externes/nommés autres que le réseau `proxy`, pilote ou
  options de réseau.

Les messages d'erreur sont explicites et ne recopient pas de contenu secret du
fichier. Tests de contournement : `compose-safety.test.ts`.

### S2 — Détournement de trafic par labels Traefik (Haute, 8.7)

`CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:H/A:N`

Le Traefik de l'hôte lit les labels des conteneurs du réseau `proxy`. Le
contrôle refuse les routeurs TCP/UDP, les plugins Traefik et les labels réservés
`coolify.*`. Lorsque les domaines autorisés du projet sont fournis, les règles
de routeur HTTP doivent se limiter par `Host(...)` à ces domaines ; les règles
sans `Host` ou avec `HostRegexp`/`HostSNI` sont refusées. Cela empêche le
hameçonnage sur un domaine de la plateforme ou d'un autre client et
l'interception de trafic.

### S3 — Volumes et réseaux externes (Haute, 8.5)

`CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:N`

Volumes externes, noms forcés, pilotes/options de volume, réseaux externes ou
nommés (hors `proxy`) et pilotes/options de réseau sont refusés, afin d'éviter
de monter le volume d'un autre projet ou de rejoindre ses réseaux.

### S4 — Sous-domaines de la plateforme (Haute, 7.6)

Un projet ne peut pas recevoir un sous-domaine réservé de la plateforme (par
exemple `api`, `coolify`, `uptime`…). Corrigé (`lib/reserved-subdomains.ts`).

### S5 — Isolement réseau entre clients (Moyenne, 6.5)

`CVSS:3.1/AV:N/AC:H/PR:L/UI:N/S:C/C:H/I:L/A:N`

Les applications et bases managées sont sur le réseau Docker de Coolify : une
application peut joindre la base d'un autre client par son nom. Les mots de
passe générés limitent le risque, mais tout service sans mot de passe (Redis
mal réglé, interface d'administration interne) devient accessible. **Piste** :
une « destination » Coolify (réseau) par organisation (`/servers/{uuid}/destinations`,
`destination_uuid` à la création).

### S6 — Adresse du client falsifiable (Moyenne, 5.3)

`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N`

`getClientIp` retenait la 1re entrée de `X-Forwarded-For`, choisie par le
client. **Correctif portail** : la dernière entrée est retenue (ajoutée par le
proxy de confiance), avec `TRUSTED_PROXY_HOPS` pour plusieurs proxys. **À
vérifier** : Better Auth lit `x-forwarded-for` avec sa propre logique
(`auth.ts`, `advanced.ipAddress`) ; confirmer sur le serveur que Traefik
réécrit cet en-tête (comportement par défaut sans
`forwardedHeaders.insecure`).

### S7 — CSP non appliquée (Moyenne, 5.4)

La politique est envoyée en `Content-Security-Policy-Report-Only` : elle signale
mais ne bloque rien. **Piste** : analyser les rapports, puis passer en
`Content-Security-Policy` (procédure dans `lib/security-headers.mjs`).

### S8 — Horodatage FedaPay (Faible, 3.1)

`verifyFedapaySignature` rejette désormais les horodatages trop anciens ou dans
le futur (fenêtre de ±5 min, comparaison en temps constant).

### S9 — Kkiapay sans identifiant partenaire (Info)

Une transaction vérifiée peut être acceptée sans `partnerId` si le montant
correspond ; le rejeu reste bloqué par l'unicité `(provider, providerRef)`.

## Recommandations hors code

1. Après déploiement des correctifs S1–S3, **relancer le déploiement des projets
   compose existants** : ceux qui utilisaient une clause désormais refusée
   échoueront avec un message explicite, à corriger avec le client.
2. Vérifier sur le serveur qu'aucun conteneur client n'a déjà ces clauses :
   ```bash
   docker ps -q | xargs docker inspect --format '{{.Name}} priv={{.HostConfig.Privileged}} caps={{.HostConfig.CapAdd}} pid={{.HostConfig.PidMode}} net={{.HostConfig.NetworkMode}}'
   ```
3. Jeton Coolify : ne lui donner que les permissions utiles (`read`, `write`,
   `deploy`, `read:sensitive`), le renouveler s'il a pu fuiter.
4. Mettre Coolify et les outils de supervision derrière le réseau privé (#169).
5. Traiter S5 (isolation réseau par organisation/destination) et vérifier S6
   côté Better Auth/Traefik ; planifier le passage de S7 en CSP enforce après
   analyse des rapports.
